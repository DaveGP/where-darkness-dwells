## How to read the concepts

The PNGs are **material and hierarchy concepts**, not screenshots, implementation blueprints, final type specimens or approved content. The guide's measured values and current game data take precedence. Do not extract the generated words, card rules, logos, floor layouts or supposed mechanics into production.

Known deviations found during visual review:

- Combat: generated cards incorrectly pair hero names with enemy names, repeat amber rails, invent card effects/status terms (including “Frailty” and “Restraint”), alter health maxima, omit parts of the controls and use serif rules. None is proposed. Real cards use their actual owners' colours, names and signature marks; the full controls remain; Source Sans 3 supplies rules. Hero health fills should be shared dark crimson, not ownership colours. Actual enemy intent plaques must include the target whenever it is known.
- Map: top-bar symbols/counts are decorative invented data, not extra resources; use actual party health, deck, keepsake and clue bindings only. The sample floor plan is illustrative, not generated by Core, and its cellar connection is not a valid route specification. The current-room gold edge must coexist with the room type identity. Final labels, rooms and doors come only from state.
- Controls: the invented tabs “Supplies” and “The Siege”, fortress-card illustration, prose about recruitment and giant ownership badge are not proposed navigation, content or mechanics. Final cards remain 150×210 with no art window. The selected button's apparent glow is conceptual; USS uses a painted rim/border, with restrained intensity. Use the exact hex tokens from the guide rather than sampling pixels or trusting generated hex lettering.
- All PNGs: texture, apparent colour contrast, serif shapes, margins, bevel depth, icon marks and ornament are approximate. Reduce corner ornament at small sizes. Bust portraits are no longer commissioned. Production uses twelve original 64×64 signature marks in former portrait slots, retaining live model portraits only on the party roster when available. The SVG shows only the original six owners with geometric mark placeholders; it does not cover the expanded roster.

## Card companion

Open the SVG at **100%** to judge the six upper cards' native dimensions. The lower state diagrams deliberately use wider 190×164 boxes to label the separate channels; they are not an alternative card size. This SVG uses the system sans-serif as the documented font-download fallback and contains layout test copy, not new cards. It validates the proposed allocation visually, not every existing card's copy fit. The future Unity audit must check the longest actual rules, all 66 content owner pairs, rendering over the stage, font metrics and 720p scaling.

The PNGs have been visually inspected. No Unity build, font download/import, production asset creation, runtime change or in-Editor readability verification was performed. Those belong to a later implementation task. The full proposed asset inventory, slices, selector contracts, contrast results and acceptance steps are in the guide.
